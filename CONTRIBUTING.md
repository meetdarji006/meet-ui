# Contributing to MeetUI

First off, thank you for considering contributing to MeetUI! It's people like you that make MeetUI such a great tool.

## How Can I Contribute?

### Adding New Components
We love new components! Please follow our [Adding Components Guide](docs/ADDING_COMPONENTS.md) to ensure your component fits into the library seamlessly.

### Reporting Bugs
This section guides you through submitting a bug report for MeetUI. Following these guidelines helps maintainers and the community understand your report, reproduce the behavior, and find related reports.

- Use the **Bug Report** template when creating an issue.
- Describe the exact steps which reproduce the problem.
- Provide specific examples to demonstrate the steps.

### Suggesting Enhancements
This section guides you through submitting an enhancement suggestion for MeetUI, including completely new features and minor improvements to existing functionality.

- Use the **Feature Request** or **Component Suggestion** templates.
- Explain why this enhancement would be useful to most MeetUI users.

## Styleguides

### Git Commit Messages
- Use the present tense ("Add feature" not "Added feature")
- Use the imperative mood ("Move cursor to..." not "Moves cursor to...")
- Limit the first line to 72 characters or less
- Reference issues and pull requests liberally after the first line

### Coding Standards
- Use TypeScript for all new components.
- Use Tailwind CSS for styling.
- Follow the existing component structure and naming conventions.
- Ensure your code is linted and formatted before submitting a PR.

## Pull Request Process
1. Create a new branch from `main`.
2. Ensure your changes follow the documentation and coding standards.
3. Update the `README.md` or other documentation if necessary.
4. Issue a Pull Request, describing your changes in detail.
5. Once your PR is reviewed and approved, it will be merged by a maintainer.

Thank you for your contributions!
